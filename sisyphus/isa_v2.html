Set v2

A register- and bus-level description of a small computer: four 8-bit data registers, two 16-bit pointers, six buses, and a 256-byte opcode space. The goal is a machine that can run a decent version of Tetris.

02

Buses

There are two 8-bit output buses (BX, BY) and three 8-bit input buses (BA, BB, BC). There is also a weird in-the-middle bus, BZ, connected to the input/output of registers and the input/output of memory. The names describe their role around the ALU and unary unit: BA, BB, and BC feed those units, while BX and BY carry results back out.

A bus here is just an 8-bit value path. The number of buses limits how many independent 8-bit values can move in one clock cycle. Six is enough, for example, to load the value five bytes above the stack pointer into a register in a single cycle. That does not say how fast the ALU itself is; this is only about how much data can move at once.

Why the buses are wired this way. This describes how data flows between buses. I tried to allocate everything in a way such that everything is not connected to everything else — that should help reduce capacitance / power consumption in the final thing.

Working registers. The original notes list R8, R16L, and R16H separately, but there are only four 8-bit working registers: RA, RB, RL, and RH. R16L and R16H are just RL and RH used as the low and high halves of a pointer. Any working register can drive BA, BB, BC, or BZ, and any working register can be written from BX or BZ.
Reading a bus route. Routes are written source → BUS → destination. For example, working register (dest) → BA → ALU in 1 means a working register drives bus BA, which feeds ALU input 1. working register (dest), working register (src), and working register (offset) name the working register chosen by the instruction; working register (src) | imm8 means either the source register or the immediate byte, depending on the form. PCl/PCh are the low and high bytes of the program counter, and low(addr)/high(addr) are the two bytes of a memory address.

How to read this section

Working registers

  • 0 RA 00

The source calls these R8. R16L and R16H are just RL and RH used as pointer halves.

Pointer registers

  • 0 RP

Opcode fields

dd selects the destination working register and ss selects the source working register. x selects a pointer. g = 0 means unsigned; g = 1 means signed. MMMM selects a jump condition; its top bit inverts the result. imm8/imm16 are the bytes that follow the opcode.

Bus routes

A route is written source → BUS → destination. For example, working register (dest) → BA → ALU in 1 means the destination working register drives bus BA, which feeds ALU input 1.

04

Instruction reference

The tables, notes, and bus allocations below are reproduced from the source document. Where the notes give a bus allocation, it appears directly beneath the table so the encoding and the data path can be read together.

In the Assembly column, Rd and Rs are placeholders for the working registers selected by dd and ss: RA = 0, RB = 1, RL = 2, RH = 3. Rx is a pointer register: RP = 0, SP = 1. The opcode map above substitutes the actual register names.

4.1 Binary 8-bit operations

Each operation has two forms. When the destination and source fields are different (dd != ss), the source is another working register. When they are equal (dd == ss), the instruction uses an immediate instead, and the next byte supplies its value.

These instructions add to, increment, or decrement a 16-bit pointer. The low byte goes through the ALU; the high byte goes through the unary unit.

These reuse the ADD16 datapath. The adder input is hard-coded to 1 or −1 instead of coming from a register or immediate.

The low byte goes through BZ; the high byte goes through BC and BX.

The low byte loads directly from BZ while the instruction is being fetched. The high byte goes through BC then BX, like the non-immediate MOV16.

4.5 Unary operations

There is a separate unary unit for one-register operations. It handles shifts, increment, and decrement, and it also supplies the high-byte fix-up for 16-bit addition. The ALU adds the low byte of the pointer to the 8-bit value; the carry output tells the unary unit whether to increment, decrement, or pass the high byte through unchanged.

OpcodeAssemblyAdditionalNotes
1110dd00SHL Rd—Shift Rd left by one bit.
1110dd01SHR Rd—Shift Rd right by one bit.
1110dd10INC Rd—Add 1 to Rd.
1110dd11DEC Rd—Subtract 1 from Rd.

Bus allocation

working register (dest)→BC→Unary in
Unary out→BX→working register (dest)

4.6 Microcoded ops

These take several clock cycles and are implemented as short sequences of simpler operations. They do not use the working registers as scratch space, which keeps function calls simple.

OpcodeAssemblyAdditionalNotes
111100ssPUSH Rs—Push Rs onto the stack: decrement SP first, then write the register value at SP.
111101ssPOP Rs—Pop the value at SP into Rs, then increment SP.
11111000CALL imm16imm16Call a function: push the return address (the PC after this instruction) onto the stack, then jump to imm16.
11111001RET—Return from a function: pop the saved PC from the stack and jump to it.

05

Notes & conditions

Naming conventions, stack behavior, and the condition encoding used by every jump. These are the details that make the tables above unambiguous.

  • Rd and Rs are placeholders for 8-bit working registers. The 2-bit dd/ss fields select them as 00 = RA, 01 = RB, 10 = RL, 11 = RH. R16L and R16H are just RL and RH used as pointer halves.
  • Rx is a 16-bit pointer register. The 1-bit x field selects 0 = RP or 1 = SP.
  • The stack starts at 0xFFFF and grows downward.
  • PUSH decrements SP, then writes the value to the stack in one operation.
  • CALL pushes the low byte of the return address first, then the high byte.
  • In a JMP, MMMM is one inversion bit followed by three condition bits. The flags are C (carry-out), Z (zero), N (MSB = 1), and V (signed overflow, MSB carry-in XOR carry-out).
  • Relative JMP + offsets are measured from the address after the imm8 byte has been fetched.
Reading MMMM. The table below describes the lower three condition bits. The top bit of MMMM is the inversion bit: I = 0 uses the output as written, and I = 1 inverts it. Thus 0000 is never and 1000 is always.
